# セキュリティポリシー

## 脅威モデル

Open Deck for MSFS は**信頼できるローカルネットワーク**（家庭内 Wi-Fi、
コックピット内の分離セグメント、エアギャップマシン）を想定しています。デフォルト
では:

- HTTP と WebSocket は **TLS なし**で動作します（パスワードはログインを保護
  しますが、トラフィックを暗号化しません）。
- 自動検出の UDP ビーコンは署名されていません — ネットワーク上の任意のホストが
  ゲートウェイを装うことができます。
- クライアントはホストが提供するファイルを信頼します（SHA-256 チェックは
  ドネーションブロックとインターフェースの整合性のみを保護し、サーバーの
  真正性は保護しません）。

**ゲートウェイをインターネットに公開しないでください**。信頼できないデバイスが
あるネットワークで実行しないでください。ゲストネットワークでは、別の VLAN を
使用するか、認証付きの独自のリバースプロキシを追加してください。

## すでに実装されていること

- **オプションのパスワードログイン**: `config/auth.json` の PBKDF2 ハッシュ
  （210,000 イテレーション）、TTL 12 時間のセッション、`HttpOnly` Cookie、
  `SameSite=Lax`、ネイティブクライアント用 Bearer、1 分あたり 5 回の試行制限、
  10 分間有効なワンタイム QR トークン（`/?pair=` 経由でのみ受け付け）。
- ホスト起動時とブラウザ内での重要ファイルの整合性チェック（SHA-256）。これは
  偶発的/意図的な改変に対する障壁であり、暗号学的保護ではありません:
  マニフェストは `--write` コマンドで再計算できます。
- CSP `default-src 'self'`、外部リソースの禁止。
- リクエストボディサイズの制限、プロファイルとコマンドの検証。
- CORS は無効: サードパーティのページは API 応答を読み取れません。
- ブラウザの POST/PUT と WebSocket に対する `Origin` チェック: 外部の Origin は
  `403` を受け取ります（Origin のないクライアントは許可されます）。
- ローカル名と IP の一覧に対する `Host` チェック — DNS リバインディングへの
  保護。未知の Host は `403` を受け取ります。
- 認証なしで残るのはログインページ、`/api/health`、`/api/integrity`、
  `/api/donation` のみです（ライセンス要件）。パスワードが設定されていない場合、
  ゲートウェイはコンソールに警告を表示します。
- Android: WebView 遷移の許可リスト、ドネーション内の `http(s)` リンクのみ、
  file/content アクセスの無効化。

## 脆弱性の報告

**公開 issue を開かないでください**。非公開チャネルを使用してください:

- GitHub → Security → **Report a vulnerability**（Security Advisories）、または
- `security@example.invalid` へのメール（公開前に実際のアドレスに置き換えて
  ください）。

バージョン、再現手順、期待される動作/実際の動作を含めてください。7 日以内に
回答します。
